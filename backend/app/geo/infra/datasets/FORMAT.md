# Формат датасета газеттира

Файл датасета — **наш собственный формат**, а не формат поставщика. Сырые данные любого
поставщика (GeoNames, OSM, Natural Earth, …) приводятся к нему отдельным **адаптером источника**
при подготовке новой версии датасета; результат заливается ассетом GitHub Release и прописывается
в `manifest.toml`. Загрузчик знает только этот формат —
смена или добавление поставщика не трогает ни загрузчик, ни базу, ни код выше.

```
сырые данные поставщика ──адаптер──▶ CSV этого формата (Release) ──загрузчик──▶ geo_places
```

## Файл

- CSV (RFC 4180), UTF-8, первая строка — заголовок, сжат gzip (`*.csv.gz`).
- Набор колонок — ровно как ниже; порядок не важен.
- Одна строка — одно место.

## Колонки

| Колонка | Обязательна | Значение |
|---|---|---|
| `external_id` | да | Ключ места у поставщика **с префиксом источника**: `GeoNames:524901`. Из него выводится наш `id` места (uuid5) — один и тот же `external_id` всегда даёт один и тот же `id`, поэтому менять его у существующего места нельзя |
| `kind` | да | Тип места: `city`, в будущем `lake`, `river`, `mountain`, … |
| `name_en` | да | Имя на английском — фолбэк отображения для любого языка |
| `name_ru` | нет | Имя на русском. Пусто — перевода нет |
| `country_code` | нет | ISO 3166-1 alpha-2 (`BY`). Пусто — у места нет страны (море, океан, Антарктида) |
| `latitude`, `longitude` | да | Точка места в градусах WGS 84 |
| `population` | нет | Население. Пусто — неприменимо (у озера) |

Имена — колонкой на язык, как и в `geo_places`. Новый язык = новая колонка здесь, в таблице и в
`Language` / `PlaceNames`.

## Загрузка

- Место загружается upsert'ом по `id`: повторная загрузка того же файла ничего не меняет, новая
  версия обновляет существующие места и добавляет новые. **Места не удаляются** — на их `id`
  ссылаются поездки.
- Что уже загружено, помнит таблица `geo_dataset_loads` (`name`, `version`, `sha256`) — загрузчик
  пропускает датасет, если эта версия уже в базе.

## Лицензия

Текущий датасет `geonames-cities` — данные [GeoNames](https://www.geonames.org) под
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/), изменённые: только населённые пункты с
населением от 5000, только английские и русские имена. Часть русских имён — метки
[Wikidata](https://www.wikidata.org) под [CC0](https://creativecommons.org/publicdomain/zero/1.0/)
(см. ниже).

## Русские имена из Wikidata

У GeoNames русского имени нет примерно у двух третей мест. Пробел закрывает обогащение
`python -m app.geo.infra.datasets.wikidata`: оно берёт файл датасета и пишет его новую версию.

- Имя ищется только у места **без** `name_ru` и с населением не меньше `--min-population`
  (по умолчанию 100 000). Заполненные имена не меняются.
- Объект Wikidata находится по id GeoNames (свойство P1566), берётся его метка `ru`.
  Уточнение в скобках в конце срезается: «Орай (город)» → «Орай».
- Метки без кириллицы (латиница в поле `ru`) и с запятой («Айвенго, штат Виктория, Австралия»)
  отбрасываются.
- Если на один id GeoNames приходятся объекты с разными метками, имя не берётся: угадывать
  хуже, чем показать английское.

## Споры GeoNames и Wikidata

Когда русское имя есть и у GeoNames, и у Wikidata, и они различаются не только «ё»/«е», дефисом,
пробелами или регистром, — это спор. GeoNames в споре проигрывает чаще: падежные формы
(«Херефорде»), переведённые слова («Савиньи-ле-храм»), имя района вместо города («Туньси» вместо
«Хуаншань»). Но и Wikidata ошибается («Посёлок Загорье», «Клайпедское городское самоуправление»),
поэтому победителя выбирает арбитр, а не правило.

- Решения лежат в `ru_name_decisions.csv` рядом с манифестом, в git: `external_id`, оба спорящих
  имени, выбранное `name_ru`, кто решил (`llm` / `human`) и причина. Сборка только применяет их —
  повторная сборка даёт тот же результат.
- Решение действует, пока спорят те же имена. Изменилось имя в GeoNames или метки Wikidata —
  решение устарело, и спор снова идёт на арбитраж.
- Спор без решения сохраняет имя GeoNames. `--disputes-out` выгружает такие споры в JSON для
  следующего арбитража; его решения дописываются в файл, и правку видно в диффе PR.
- Решение `human` пишется руками и правит любое другое — так же исправляется ошибка арбитра.
- Решение с пустым `wikidata_ru` — правка сломанного имени GeoNames, которому спорить не с чем
  («Камогаwа» → «Камогава»). Действует, пока в GeoNames то же имя и спора по месту нет.
- Файл ограничен числом споров и найденных поломок, а не размером датасета. Если правок без спора
  становится много — это систематическая ошибка, и её чинят правилом в сборке, а не списком.
