# Roadmap: Journeys

Задуманное, но ещё не начатое развитие раздела Journeys. Это список идей и открытых решений, а не
план: каждый пункт перед реализацией проходит отдельное обсуждение и `/feature-plan`. Отгруженное
отсюда удаляется — история живёт в `CHANGELOG.md`.

## Исходная точка модели

`Journey` — это **один отрезок** `origin → destination` (транспорт, год,
`distance_km` по прямой), а не путешествие целиком. Маршрут Минск – Москва – Стамбул – Минск лежит
в базе тремя записями. Почти всё ниже упирается в этот факт.

## Статистика

Отдельный пункт меню: сводку над лентой «Все путешествия» решили не делать.

- Число перелётов; км по воздуху / воде / суше.
- Страны (N из 195) и города.
- Самый частый маршрут, самый дальний отрезок, первая и последняя поездка.
- Сравнения: «3,2 экватора» (40 075 км), «18 % пути до Луны» (384 400 км).

`distance_km` считается по большому кругу — для самолёта это почти правда, для поезда и машины
реальный путь длиннее. Подписывать «по прямой».

## Wishlist — места, где хочется побывать

- **Элемент:** страна (ISO alpha-2, по контракту из `architecture.md`) или место (`placeId` из
  справочника geo) — `kind: country | place` плюс соответствующие поля.
- **Отдельный bounded context**, не часть `journeys`: свой жизненный цикл, при распиле уезжает
  отдельно.
- **«Сбылось!»:** когда появляется поездка в страну/город из списка, пункт не удаляется, а
  помечается сбывшимся с датой. Вычисляется на чтении через узкий клиент к `journeys` (по образцу
  `InternalUsersClient`), не через события.
- **На карте:** страны — штриховкой или контуром отдельного цвета, города — полыми маркерами;
  третий цвет, не спорящий с оранжевым «был».

**Открытое решение — имя домена.** «Add place» (отметить место посещённым без поездки) — та же
сущность со статусом «был». Назвать домен `places`, а не `wishlist`, — и Add place ляжет в него
без редизайна.

## Ввод поездок

- **Ввод цепочкой:** Минск → Москва → Стамбул → Минск за один раз создаёт три отрезка. Главная
  боль ввода реальных путешествий и естественный путь к `Trip`.
- **Origin по умолчанию = последний destination:** следующий отрезок начинается там, где кончился
  предыдущий.

## Визуализация

- **Итоги года:** экран «2025 в поездках» с анимацией дуг на глобусе — место, где глобус уместнее
  плоской карты.
- **Тепловая карта городов** на Journeys map: размер точки растёт с числом визитов.
- **Общий слой 2D-карты для вкладок Journeys:** одна карта переживает переход между картой
  путешествий, картой перемещений и лентой и перелетает к новому кадру, а не создаётся заново на
  каждой вкладке (как персистентный глобус).

## Справочник мест

- **Русские названия для мест без перевода.** После `geo-data-v2` русское имя есть у 47.6% мест
  (Wikidata дописала всё, что у неё было; споры с GeoNames решены арбитром). Остаток — ~36 тысяч
  мест, которых нет в Wikidata по-русски, в основном городки до 15 000 жителей. Следующий шаг —
  LLM-транскрипция с пометкой `decided_by=llm` в файле решений и выборочной проверкой.
- **Страна у поездки для мест без страны.** `journeys.country_code` пока NOT NULL: выбрать можно
  только города. Когда станут выбираться моря, озёра и горы (`kind`), решить, куда такие места
  попадают на карте стран.
- **Настройка поиска под не-городские датасеты.** Когда в газеттире появятся места других `kind`,
  замерить поиск на коротких префиксах и решать тогда: частичные индексы или партиционирование по
  `kind`, заранее посчитанный топ для 2–3 символов.

## Порядок

1. Статистика — только чтение, агрегаты в SQL.
2. Wishlist — новый домен, таблица, миграция.

Ввод поездок и визуализация встраиваются по мере готовности соседних пунктов.
