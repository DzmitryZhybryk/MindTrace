## Requirements

- Подключить пять недостающих `/v1/auth/*` роутов: login, logout, refresh, email/send-verification, email/verify.
- Email не блокирующий: пользователь после регистрации попадает на `/` со всеми правами; верификация — опциональна.
- Soft-nudge: баннер сверху главной + пункт «Verify email» в profile-menu с бейджем.
- Верификация живёт в одной модалке `<VerifyEmailDialog>`, общей для трёх точек входа (баннер, profile-menu, будущий JIT).
- Заложить хук JIT-гейта: `apiFetch` различает 401 `auth.email_not_verified` и эмитит событие «открыть модалку верификации».
- Banner dismiss — на сессию (sessionStorage).
- Refresh-flow: single-flight на 401, на старте `ProtectedRoute` пробуем `refresh()` если токена нет.
- `AuthContext` как источник правды для `{accessToken, claims, isAuthenticated, openVerifyDialog, ...}`.

## Risks

- MEDIUM: Secure cookie на dev http — проверка в Phase 2; если падает, отдельный тикет на is_dev флаг на бэке.
- MEDIUM: различение 401 по `body.code` в apiFetch (invalid_credentials/invalid_refresh_token/email_not_verified/invalid_access_token).
- MEDIUM: single-flight refresh — shared Promise модульный, обнуляется в finally.
- LOW: JWT decode без верификации — только UI-флаг.

(Заметка: `syncVerifiedClaim` всё ещё зовёт `refresh()` напрямую, но там одиночный user-triggered вызов без конкуренции — rotation-гонки нет, оставлено как есть.)
- QA-правка (D2, bootstrap double-refresh): на reload с пустым access_token прилетало два `POST /refresh/` (401 + 200). Причина: StrictMode (dev) дважды запускает bootstrap-эффект в `AuthContext`, а тот звал `refresh()` **напрямую**, мимо single-flight. Два параллельных refresh с одной cookie → reuse-detection на бэке (`auth_service.py` OAuth 2.1) → `revoke_all_active_by_user_id` ревокает и только что выданный новый токен → refresh-цепочка тихо рвётся (сессия живёт лишь до истечения access-токена). Фикс: bootstrap прогнан через тот же `ensureRefreshed()` (`api/client.ts`, теперь экспортируется) — обе StrictMode-итерации шарят один module-level promise → ровно один `/refresh/`. `AuthContext` больше не пишет токен сам (это делает `ensureRefreshed` на успехе). tsc зелёный.
- QA-правка (error-стиль): `index.css` — глобальный override Mantine error-состояния инпутов. Поле в ошибке остаётся нейтральным (рамка `gray-4`, обычный текст/плейсхолдер/иконка), красным остаётся только сообщение под полем; на фокусе сохраняется обычная focus-рамка. Цепляется за стабильный `.mantine-Input-wrapper[data-error]`, покрывает все формы.
